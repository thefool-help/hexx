# 海克斯棋（Hex）— 界面 + 决策代码

一个可直接在浏览器中运行的海克斯棋（Hex）人机对战程序，包含**图形界面**、
**胜负判定**、**棋局评估**与**AI 行棋决策**三大部分，对应课程实验的“界面设计与判定 /
行棋策略 / 棋局评估”分工。

## 运行方法

**方式一（推荐，最简单）**：双击 `index.html`，用浏览器（Chrome / Edge / Firefox）打开即可。

**方式二**：在项目目录启动任意静态服务器后访问，例如：

```bash
# Python 3
python -m http.server 8000
# 然后浏览器打开 http://localhost:8000
```

> 说明：本程序不依赖任何第三方库、无需安装、无需联网，纯原生 HTML5 + JavaScript 实现。

## 规则实现要点（`js/game.js`）

- 棋盘为 N×N 菱形六边形网格，采用**轴向坐标** `(r, c)`。
- 红方（先手）连通**上、下边界**获胜；蓝方连通**左、右边界**获胜。
- 六个邻居方向：上、右上、左、右、左下、下。
- **胜负判定** `isWinAfterMove`：从刚落下的子出发做广度优先搜索（BFS），
  只沿同色相邻格子走，若同时触及己方两条对边即获胜。相比全盘扫描，该写法
  只搜索新落子所在连通块，适合在搜索树中高频调用。

## 棋局评估（`js/game.js`）

评估使用海克斯棋最经典的**“两色连通距离差”**思路：

1. 把局面看作一张图：己方棋子可“免费”通过（代价 0），空格需“再落一子”
   （代价 1），对方棋子是障碍（不可通过）。
2. 用 **0-1 BFS**（双端队列 BFS，时间复杂度 O(N²)）计算某色从起始边连到目标边
   的**最短代价**，即“还需要几步才能连成”。
3. `evaluate = 对方距离 − 己方距离`：正值表示己方更接近胜利，负值表示劣势。
4. **双杀检测**：计算最短距离的同时统计“一步即可取胜的目标格数量”（宽度）。若某方距离为 1
   且宽度 ≥2，说明它有多个绝杀点、对手无法同时封堵（双杀）→ 评估直接取到近乎必胜 / 必败的
   大值。这条弥补了纯距离差评估看不出双杀威胁的盲点，避免“地平线效应”导致堵不住。

例如空棋盘上红、蓝都需 N 步，评估为 0（均势）；红方某列已连成则距离为 0，
评估取到必胜大值；若对手出现双杀点，评估取到近乎必败的大负值。

## 行棋策略 / 决策代码（`js/ai.js`）

`findBestMove(board, N, color, {timeLimitMs, maxDepth})` 返回当前最佳落点，综合了：

1. **战术先手**：若一步即可获胜，直接走；若对手存在一步获胜点，立即抢占封堵。
2. **候选落点剪枝**：只考虑与已有棋子切比雪夫距离 ≤2 的空格，并按“热度 + 中心偏好”排序，
   大幅缩小搜索分支。
3. **迭代加深 + Alpha-Beta 剪枝（fail-soft）**：由浅入深搜索，每层都取完整解，超时也能返回上一层可靠结果。
4. **置换表（Zobrist 哈希）**：用确定性 xorshift 随机数做 Zobrist 键，缓存精确值 + 上/下界
   标记与最优着法，跨深度复用搜索结果，并实现 PV 排序。
5. **走法排序**：置换表最佳着 → 杀手着法 → 根节点静态评估排序，大幅提升剪枝效率。
6. **限时搜索**：搜索过程中周期性检查时间，真正超时立即安全返回，保证界面不卡死。

难度映射：简单 = 深度 5 / 0.4s；中等 = 深度 9 / 2.5s；困难 = 深度 16 / 10s。

## 界面与功能（`js/ui.js`、`index.html`）

- HTML5 Canvas 绘制菱形六边形棋盘，红/蓝边界高亮提示各自连通目标；
  棋子为略小于格子的圆形，带立体渐变与阴影；最近一步高亮、悬停预览、提示高亮。
- 菜单：棋盘大小（5/7/9/11/13）、对局模式（人机执红 / 人机执蓝 / 双人 / AI 观战）、
  AI 难度（简单/中等/困难）。
- 按钮：新游戏、悔棋（人机模式回退一整轮）、提示、AI 落子、暂停/继续（AI 观战）。
- 状态栏实时显示当前回合、胜负、已落子数、AI 搜索深度与访问节点数。

## 扩展建议

- 想更强：可把评估改成更精确的“双距离”启发，或加入蒙特卡洛树搜索（MCTS）；
- 想更稳：可给置换表加入上下界标记、使用增量式 Zobrist 哈希；
- 想跨语言：核心逻辑集中在 `game.js`，可平移到 C++ / Python 用于课程报告。
